# Notes

attempt-01: Wrote the function from scratch rather than from A.r3. Hot path: bounds check len>=2, movbe key length, bounds check, one byte load per VInt with a sign test; single-byte VInts (the common case) take no further work. Multi-byte VInts use lzcnt for the width, a bounds check, and a byte loop to assemble the value (the first VInt's value is never needed, so only its width is computed). No stack use, no callee-saved registers, no panic paths. Error returns 24 (1 + Eof as the compiler's code shows). Result: PASS, 24.59 cycles/op vs 26.04 for A.r3 (ratio 0.945, 53 vs 85 instructions). Branch misses slightly higher (0.042 vs 0.029). The gain is mostly fewer instructions; the loop is latency-bound by the dependent loads of the chain walk, so the benchmark harness probably dominates. Single counted attempt used; I did not try further variants since I could not identify a change that shortens the dependent load chain.
